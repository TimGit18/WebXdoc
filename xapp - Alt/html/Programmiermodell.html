Java-Programmiermodell

Die Programmierung in Java bedeutet die Konstruktion und Implementierung objektorientierter Anwendungen. Diese Anwendungen bestehen aus Klassen, die in Paketen organisiert sind. Diese Klassen enthalten Daten und Methoden. Die Daten repräsentieren den Zustand, die Methoden das Verhalten der Objekte der Anwendung, wobei Objekte die Instanzen von Klassen sind. Die Programmierung selbst ist Bestandteil der Java-Technologie. Diese besteht aus einem Entwicklungswerkzeug, dem Java Development Kit (JDK) für die Programmierung von Java-Anwendungen, und einer Laufzeitumgebung, der Java Runtime Environment (JRE) für die Ausführung dieser Anwendungen.

Java Development Kit

Der Java Development Kit ist ein vollständiges Entwicklungssystem für Java. Das Entwicklungssystem umfasst den Compiler, die Kernbibliotheken (Core APIs) und die Laufzeitumgebung Java Virtual Machine (JVM). Der interne Compiler javac übersetzt die Java-Quelldateien in Klassendateien. Die Klassendateien liegen in Bytecode vor, welcher zur Laufzeit virtualisiert, d.h. von der virtuellen Machine interpretiert wird.

Java Runtime Environment

Das reduzierte Laufzeitsystem zur Ausführung fertig übersetzter Java-Anwendungen ist das Java Runtime Environment. Es beinhaltet die Java Virtual Maschine und die Laufzeitbibliotheken. Das Laufzeitsystem ist für den reinen Betrieb von Java-Anwendungen ohne Entwicklung geeignet und wesentlich kleiner als das komplette Entwicklungssystem.

Achtung:

Die maximale von Oracle angebotene JRE Version ist die JRE 8. Der aktuelle JDK hat allerdings die Version 21. Software, die mit dieser Version entwickelt wurde, ist auf einer älteren JRE nicht ausführbar. Man sollte daher die im JDK mitgelieferte aktuelle JRE als Runtime Environment verwenden.

Java Virtual Machine

Die Java Virtual Machine (JVM) ist die eigentliche Laufzeitumgebung. Sie interpretiert den Bytecode, der vom Java Compiler durch Übersetzung erzeugt wird. Als virtueller Prozessor arbeitet die Virtual Maschine die Maschineninstruktionen ab und entkoppelt somit den Bytecode vom Betriebssystem. Sie lädt über den Class Loader die Java-Klassen zur Laufzeit der Anwendung und instantiiert diese dynamisch.

Zusammen mit der Java API bildet die Java Virtual Machine die Java-Plattform. Anwendungen kommunizieren mit dem Betriebssystem nur über die Virtual Machine und die Programmier-Schnittstellen.
